# AGENTS.md

FastAPI learning project (`app/main.py` → `app.main:app`) with sklearn `/predict` (+`/train`), multi-provider `/chat` + `/mida-assistant` (Anthropic or OpenRouter, picked by `LLM_PROVIDER`; the latter is a scoped support-bot persona grounded from `docs/`), `/docs/scrape` + `/docs/list` (URL → Markdown ingestion tool for that grounding), the same tools re-exposed over MCP (`app/mcp_server.py`, see `.mcp.json`) for MCP-aware agents, OpenCV `/cv/grayscale`, plus k8s practice manifests. No CI, no lint/typecheck config, no package manager beyond pip + `requirements.txt`.

## Commands

- Tests: `.venv/bin/python -m pytest -q` — single test: `.venv/bin/python -m pytest tests/test_health.py -q`
  - Note `.vscode/settings.json` enables unittest discovery, but the repo's only test suite is pytest; run pytest explicitly.
- Dev server: `.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8888` — port is **8888**, not the 8000 default (Dockerfile, k8s Service, probes all assume 8888).
- Lint/format (no config files, tools only listed in `requirements.txt`): `ruff check .`, `black .`
- Docker: `docker build -t py-app:local .` — base `python:3.12-slim` (code dùng syntax `X | None` nên **không** chạy được trên 3.9). `opencv-python-headless` thay vì `opencv-python` vì image slim thiếu `libGL`.

## Architecture / gotchas

- Entrypoints: `app/main.py` wires `health`, `predict`, `chat`, `cv`, `db` routers from `app/api/routes/`. Schemas in `app/schemas/common.py`. `pandas`/`sqlalchemy`/`psycopg2-binary` còn trong requirements cho bài Postgres nâng cao; `torch`/`langchain*` đã gỡ vì không gì import.
- Config: `app/core/config.py` uses `pydantic-settings` (`APP_NAME`, `DEBUG`, `DATABASE_URL`, `ANTHROPIC_API_KEY`, `CHAT_MODEL`, `LLM_TIMEOUT`, `MODEL_PATH`, `SUPABASE_URL`, `SUPABASE_KEY`, `LLM_PROVIDER`, `OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, `OPENROUTER_MODEL`, `.env` file). `get_settings()` is `@lru_cache`d — env is read once at import, so **config changes require a process/pod restart**, never hot-reload. In tests, always `get_settings.cache_clear()` both before and after `monkeypatch.setenv(...)`.
- Supabase: `app/db/supabase_client.py` + `GET/POST /db/todos`, `GET /db/health` (via `supabase-py` PostgREST, table `public.todos`). Local key lives in `.env` (gitignored); k8s ships URL in ConfigMap + key placeholder in `k8s/secret.yaml`. `DATABASE_URL=sqlite:///./app.db` is unrelated — only `GET /health`'s SQLAlchemy ping reads it (`app/api/routes/health.py`); it has nothing to do with Supabase.
- **Q&A session logging (`app/db/qa_log.py`)**: `/chat`, `/mida-assistant`, and the MCP `ask_mida_assistant` tool each call `log_qa_session(endpoint, user_message, answer, extra=...)` after a successful reply, inserting into Supabase table `qa_logs` (migration: `supabase/migrations/0002_create_qa_logs.sql` — run it in the Supabase SQL editor before this does anything). Best-effort: any failure (missing creds, network, table not migrated yet) is caught and falls through to `app/core/error_log.py` instead of breaking the response. **Because `.env` already has real `SUPABASE_URL`/`SUPABASE_KEY`, every success-path test for these three call sites must mock `log_qa_session` (`monkeypatch.setattr(<module>, "log_qa_session", lambda *a, **k: None)`)** — otherwise the test suite makes real Supabase writes.
- **Local error log (`app/core/error_log.py`)**: `log_error(source, error, context)` appends one JSON line to `logs/errors.jsonl` (gitignored, created on first write); `search_errors(keyword)` greps it back. Used today only as `qa_log`'s failure fallback, but it's the general-purpose place to record a failure worth remembering — check `search_errors(...)` for a matching `source`/`error` before re-debugging something that's failed here before.
- Secrets: copy `.env.example` to `.env` (gitignored). Never commit real keys; `k8s/secret.yaml` ships with an empty `ANTHROPIC_API_KEY` placeholder.
- `/predict` is seeded with a demo model at startup (`lifespan` in `app/main.py`: `y = 2x0 + 3x1 + 1`), retrainable via `POST /predict/train` (persisted to `MODEL_PATH`, `*.joblib` gitignored). `/chat` calls the real LLM API — no key = `500`, don't hit it in automated tests (mock, see below).
- **Multi-provider LLM (`app/llm/provider.py`)**: `get_llm_client()` is the one switch — reads `LLM_PROVIDER` (`"anthropic"` default or `"openrouter"`) and returns either `LLMClient` (`app/llm/client.py`, Anthropic SDK, default model `claude-3-5-sonnet-latest`) or `OpenRouterClient` (`app/llm/openrouter_client.py`, raw `httpx` against OpenRouter's OpenAI-compatible `/chat/completions`, default model `anthropic/claude-3.5-sonnet`). Both expose the same `ask`/`ask_with_system` contract, so `/chat`, `/mida-assistant`, and `app/mcp_tools.py` never branch on provider themselves — they all call `get_llm_client()`. Missing API key for whichever provider is selected raises `RuntimeError` → `500`; an unrecognized `LLM_PROVIDER` value also raises `RuntimeError` → `500`. **In route tests, mock `<route_module>.get_llm_client`, not `LLMClient` directly** — routes import the factory, not the client class.
- `/mida-assistant` (`app/api/routes/mida_assistant.py` + `app/llm/mida_prompt.py`): "MIDA Assistant" Shopify fraud-app support persona, scoped to fraud/bot-blocking topics only. `SYSTEM_PROMPT` is static (passed via the provider's `system` param); per-request context (`retrieved_chunks`, `customer_config`, `feature_catalog`, `recent_history`) is assembled into the user turn by `build_user_content` and is always treated as data, never as instructions (anti prompt-injection rule baked into the system prompt itself). If a caller (chat agent) doesn't pass `retrieved_chunks`, the route auto-fills them via `app/tools/doc_retriever.retrieve_relevant_chunks` — naive keyword overlap over `docs/*.md`, not a vector store; swap that one function to upgrade retrieval later. The model must reply with a single JSON object (`answer`, `cited_sources`, `suggested_features`, `confidence`, `needs_escalation`, `in_scope`); `parse_assistant_reply` validates/clamps it and a malformed reply surfaces as `502`, not silently forwarded.
- **MCP server (`app/mcp_server.py` + `app/mcp_tools.py`)**: re-exposes `scrape_doc`, `list_docs`, `ask_mida_assistant` as MCP tools for MCP-aware agents (Claude Code, opencode, Claude Desktop) — same logic as the HTTP routes, called directly (no HTTP hop), also provider-agnostic via `get_llm_client()`. Registered for auto-discovery in `.mcp.json` at the project root (`command: .venv/bin/python`, `args: -m app.mcp_server`, stdio transport). Run standalone: `.venv/bin/python -m app.mcp_server`. Logic lives in `app/mcp_tools.py` as plain functions specifically so it's unit-testable (mock `app.mcp_tools.doc_scraper` / `.load_docs` / `.retrieve_relevant_chunks` / `.get_llm_client`) without needing an actual MCP session — `app/mcp_server.py` itself is a thin adapter, don't add logic there.
- `/docs/scrape` + `/docs/list` (`app/api/routes/docs_tools.py` + `app/tools/doc_scraper.py`): ingestion tool a chat agent can call to refresh `/mida-assistant`'s grounding material. `POST /docs/scrape {"urls": [...]}` fetches each page (`httpx`), strips `script/style/nav/header/footer/aside`, extracts `main`/`article`/`[role=main]`/`body`, converts to Markdown (`markdownify`) and writes one `docs/<slug-of-title>.md` file per URL with a `title`/`source`/`scraped_at` front-matter header; failures per-URL are collected in `errors`, not raised. Don't hit real URLs in tests — mock `doc_scraper.httpx.get` / `doc_scraper.scrape_urls`.
  - **SSRF guard**: this endpoint fetches arbitrary caller-supplied URLs, so every hop (page + each redirect + each image) goes through `_safe_get`/`_assert_safe_url`, which resolves the hostname via `socket.getaddrinfo` and rejects loopback/private/link-local/reserved/multicast targets — `follow_redirects` is off on the raw `httpx.get` call and redirects are re-validated manually instead. Don't bypass this by calling `httpx.get` directly elsewhere for scraped URLs.
  - **Image handling (OpenCV)**: `<img>` tags are never kept as markdown image links (which would otherwise dump raw URLs/base64 into the agent's context). `data:` URIs are dropped outright (can carry MBs of base64). Remote `<img src>` is fetched (through the same SSRF-guarded `_safe_get`), decoded with `cv2.imdecode` purely to read dimensions, and replaced with a short `"[Hình: <alt> (WxH)]"` placeholder — or dropped entirely if the smaller side is under 48px (assumed icon/spacer). Any fetch/decode failure falls back to `"[Hình: <alt>]"` or is dropped; a broken image never fails the whole scrape.

## Kubernetes (see `docs.md` for full walkthrough)

- Basic manifests: `k8s/{configmap,secret,deployment,service}.yaml`. `k8s/advanced/` is opt-in practice material (postgres, hpa, ingress, networkpolicy, cronjob, namespace) — **do not `kubectl apply` it by default**.
- kind flow: `kind create cluster --name py-practice` → `docker build -t py-app:local .` → `kind load docker-image py-app:local --name py-practice` → `kubectl apply -f k8s/`. `imagePullPolicy: IfNotPresent` means pods will fail with `ImagePullBackOff` if you skip the `kind load` step. Docker Desktop Kubernetes skips `kind load` (shared daemon).
- `kubectl rollout restart deployment py-app` is required after **both** kinds of change: rebuilding the image under the same `:local` tag (tag string unchanged, so no auto-update), and editing ConfigMap/Secret (`envFrom` does not watch for changes). `kubectl port-forward svc/py-app 8888:8888` is needed to reach the `ClusterIP` service locally.
